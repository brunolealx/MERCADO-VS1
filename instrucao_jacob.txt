Nosso projeto possui um componente customizado chamado 'JacobNumericField' 
(localizado em br.com.creativex.ui.components). 
Este componente replica o comportamento de máscaras de calculadora e campos numéricos COBOL.

O construtor dele é definido como:
new JacobNumericField(int digitosInteiros, int digitosDecimais, boolean aceitaSinal);

Regras para a refatoração do arquivo fornecido:
1. . Se o campo gerenciar dados financeiros, moedas, preços ou quantidades, substitua por:
   JacobNumericField.criarPorPicture("MÁSCARA_ADEQUADA");

2 .  Se o campo gerenciar nomes, cidades ou descrições textuais puras (apenas letras), substitua por:
   JacobTextField.criarPorPicture("A(TAMANHO)");
   
   
3. Se o campo gerenciar códigos de barras, IDs alfanuméricos ou senhas, substitua por:
   JacobTextField.criarPorPicture("X(TAMANHO)");
   
4. Localize declarações antigas de JTextField ou JFormattedTextField que gerenciam valores monetários,
 preços, quantidades ou códigos numéricos.
 
 
5. Substitua essas declarações pelo 'JacobNumericField', calculando dinamicamente o número de inteiros
 e decimais necessários com base na regra de negócio do campo.
   - Exemplos de mapeamento:
     * Preços/Valores (ex: Preço de Venda, Total, Subtotal): novos JacobNumericField(7, 2, false)
     * Quantidades (com frações): novos JacobNumericField(4, 3, false)
     * Quantidades inteiras (ex: itens de caixa): novos JacobNumericField(4, 0, false)
6. Substitua chamadas antigas de conversão manual de texto como 'Double.parseDouble(campo.getText())'
 ou 'new BigDecimal(campo.getText())' pelos métodos nativos do componente:
   - campo.getBigDecimalValue() ou campo.getDoubleValue()
7. Adicione o import correto: import br.com.creativex.ui.components.JacobNumericField;
8. Mantenha os nomes das variáveis originais, layouts e regras de negócio intocados. Retorne apenas 
o código Java completo e atualizado.
